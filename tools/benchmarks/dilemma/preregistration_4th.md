## H5 — 研究者の制約はハード・フィルタとして候補集合を読める大きさにする

**登録**: 測定前。

### 動機と、これが新しい問いである理由

第2次 §1.2 で「時代・方言・ジャンルは無効」と結論した。**これはランキング信号としての判定である。**加点は候補間を区別しないから効かない（§2.2 の一般定理：同一交替で到達した群は、共有されている情報では並べ替えられない）。

**除外は別の操作である。**加点が順序を変えるのに対し、除外は集合を小さくする。この2つは数学的に別物であり、**片方の否定はもう片方の否定にならない**。§6 のファセット UI 仮説はこの区別に立っている。

### 測定器

`dump_b3u_feat.jsonl` のみを読む（人間も UI も不要）。ファセットの定義は `rlb_rerank.py` の既存部品を再利用する：

| ファセット | 代理データ | 実装 |
|---|---|---|
| 品詞 | dump の `postag[0]`（PapyGreek gold） | `AGDT_POS` → `dominant_pos` 一致 |
| 時代 | `date_nb`/`date_na` × `by_century` | `centuries_for(row)` と交差 |
| 方言 | `by_dialect` の Koine 系 | `KOINE` |
| 語頭文字 | 候補文字列 | `b1_key(cand)[0]` 一致 |
| 適用交替 | §H4 の区画判定 | `rlb_zones.rule_reachable()` |

**代理の限界を明示する**：`postag` は PapyGreek の gold 注釈である。これは「研究者が品詞を知っている」という前提の理想化であり、実際の利用者がどれだけ正確に指定できるかは測っていない。時代はパピルスの年代（メタデータ）なので、これは実際に利用可能な情報である。

### 不明値の2方針（両方測る）

test の候補スロット 372,455 件のうち attestation エントリを持つのは **75.5%**、gold レンマは **92.8%**。この非対称が梃子なので、片方だけでは大きさが分からない。

- **conservative**: 属性が無い候補は**残す**（recall を守る、フィルタは弱い）
- **aggressive**: 属性が無い候補は**落とす**（候補を 24.5% 削り、gold は最大 7.2% 失う）

### 判定規則（測定前に固定）

> **採択**: `|C|` 中央値 **≤20** かつ **recall@∞ 保持 ≥85%**
> **棄却**: recall@∞ 保持が 85% を割る、または `|C|` 中央値が 50 を超える
> 中間は保留とし、conservative / aggressive のどちらが実用域かで判断する。

**棄却された場合の含意**：ファセット UI も死んでいることになり、製品の形を再考する。§6 は「消去法の帰結」ではなくなる。

### 報告する指標

フィルタ前 / 各ファセット単独 / 累積適用の順に：

- `|C|` 中央値・p90
- **recall@∞ 保持**（フィルタが正解を殺していないか）——最重要
- recall@5、**coverage@5**（全変異が top-5 に収まる文書の割合）

### 測定前に固定する事後観察（重要）

1. **効くファセットは品詞だけである。** century・dialect・initial・zone は単独では recall を下げるか中立。§1.2 が「ランキング信号として無効」と判定したものは、**フィルタとしても無効**だった——ただし品詞は例外で、フィルタとしては強力に効く。§6 の仮説は「研究者の制約一般」ではなく「**研究者の品詞知識**」に絞られる。

2. **`initial`（語頭文字）は有害である。** gold 保持 84.3%、recall −6.3pt。原因はギリシャ語の**加音（augment）と前接辞**——`ἀνάγκασεν → ἠνάγκασεν`、`ἐχον → ἔσχον` のように、屈折形の語頭とレンマの語頭が違う。「利用者が語頭を読める」という直感的に有望なファセットが、この言語では機能しない。

3. **`aggressive|pos` 単独が recall では最良**（81.5%、+6.3pt [+3.5, +9.1]、区間がゼロを除外）。dev の `|C|` 中央値は24であり、事前登録の閾値20を4候補上回るため判定は INCONCLUSIVE になる。**閾値は動かさない。**ただしこの構成が実用上の最良動作点であることを記録する。参考：gold POS を*ランキング信号*として使ったときの利得は +9.5pt（第1次 §5.1）であり、**フィルタとして使うと +6.3pt が、実タガーの精度問題を経由せずに得られる。**

### test で報告する構成（test を見る前に固定）

test は**一度だけ**走らせ、全表を出す。読み方は先に決めておく：

- **主報告**: `aggressive|pos`（dev で recall 最良の動作点）
- **事前登録の採択構成**: `aggressive|+pos+century+dialect`（`|C|` 最小で基準を満たす）

この2つ以外のセルは参考値として掲載するが、主張を持たせない。

### 結論と、その解釈上の制約

**1. 品詞フィルタは強いが、文脈 LM との確定比較は再測定を待つ。**

| 構成 | test recall@5 | coverage@5 | \|C\| 中央値 |
|---|---:|---:|---:|
| R0（現状） | 73.0% | 31.5% | 201 |
| ＋文脈 LM（第3次の最良、`clean.py` 修正前の暫定値） | 77.2% | 39.2% | 201 |
| gold POS を**ランキング信号**に（第1次 §5.1） | 82.5% | — | 201 |
| **品詞を*フィルタ*に** | **81.7%** | **44.1%** | **23** |

ランキング信号としての gold POS（+9.5pt）とほぼ同等の recall を得ながら、**候補集合が 201 → 23 に縮む**。ランキングは集合を小さくしない。品詞フィルタの coverage@5 は 31.5% → 44.1% だが、文脈 LM の 39.2% は `clean.py` 修正前の暫定値であるため、修正後の再測定までは両者の優位性を確定しない。

**2. 効くファセットは品詞だけである。** century・dialect・zone は単独では中立から有害。§1.2 の「ランキング信号として無効」はフィルタとしても概ね無効だった。**§6 の仮説は「研究者の制約一般」ではなく「研究者の品詞知識」に絞られる。**これは仮説の縮小であり、同時に鋭利化でもある。

**3. `initial`（語頭文字）は有害。** gold 保持 79.7%、recall −9.0pt。ギリシャ語の加音・前接辞（`ἀνάγκασεν → ἠνάγκασεν`、`ἐχον → ἔσχον`）でレンマと屈折形の語頭が違うため。直感的に有望なファセットが、この言語では機能しない。

**4. 決定的な制約——`postag` は PapyGreek の gold 注釈である。** これは「研究者が品詞を正しく指定する」という理想化であり、上限である。

ただしランキングの場合と**非対称である点が重要**：ランキングでは gold POS の +9.5pt が実タガーでは +0.9pt に落ちた（タガーが 56.9% しか当てられないため）。フィルタ UI では**タガーは介在せず人間が指定する**ので、この崩落は起きない。崩れるとすれば「人間が品詞を誤る」場合であり、それは別の量である。**本測定はその量を測っていない。**パピルス学者が非標準綴りの語の品詞をどれだけ正確に判断できるかは、人間を入れた検証（第4次の範囲外）でしか分からない。

**5. 候補ゼロが 3.4% 発生する。** フィルタが強すぎて何も残らないケース。UI では「フィルタを緩める」導線が必須であることを意味する。

## H6 — subword 文脈モデルはカウントベース LM の被覆上限を超える

**登録**: 測定前。

### 動機

H2 の機構特定はこうだった：**トライグラムは自分が見たことのある候補しか並べ替えられない。**語彙に無い候補はバックオフの床値を受け取り、他の未知候補と区別がつかなくなる。

これは**カウントベース LM 固有の制約**である。subword トークナイザを持つモデルには OOV の床が無く、未見のレンマも部分文字列から表現が構成される。したがって H2 の被覆外挿（→ §H7）で得た上限は、**この経路には適用されない**。

補強論拠：gold POS が +9.5pt を持つのに実タガーが +0.9pt しか取れなかったのは、第1次 §3.5 で「中間表現を経由すること自体が律速」と結論されている。文脈モデルは POS を*明示的な中間表現なしで*内在化するので、この診断が正しければその相当部分が届きうる。

### モデル選定（測定前に確定済み）

提案された `pranaydeeps/Ancient-Greek-BERT` は **MLM ヘッドを持たない**（safetensors 200 テンソル中 `cls.predictions.*`／`lm_head.*` がゼロ、`architectures` は `BertModel`）。pseudo-log-likelihood は原理的に計算できないので使用しない。`altsoph/bert-base-ancientgreek-uncased` も同様。

**`bowphs/GreBerta`（`RobertaForMaskedLM`、`lm_head.*` 実在、203 テンソル、vocab 52k）を使う。**

### 採点設計 — 2案をゲートで比較する

**(A) 候補を文中に差し込んで PLL、subword 数で長さ正規化**
- 利点：**OOV の床が無い**。任意の文字列を採点できる。この実験を動機づけた機構論そのもの。
- 落とし穴1：長さ正規化。素の合計対数尤度は短い候補を不当に有利にする。
- 落とし穴2：NFC/NFD。トークナイザの学習時正規化を先に確認する。
- 落とし穴3：**BERT は表層テキストで学習されており、レンマ列では学習されていない。**候補はレンマ（辞書見出し形）、文脈は屈折した表層形なので、差し込むと学習分布の外の文字列を作る。

**(B) 対象位置をマスクし、表層トークンの予測分布を辞書でレンマに写像**
- 利点：長さ正規化が不要（単一マスク位置の1回の softmax）。レンマ／表層の不一致が生じない。トライグラムの `P(lemma | context)` の直接の類似物。
- 欠点：出力 softmax は 52k の**閉じた語彙**なので、(A) の「OOV の床が無い」利点が部分的に失われる。多 subword の表層形は単一マスクで捉えられない。

**この対立は本質的なので測って決める。**dev 小標本（200トークン）で両方を採点し、勝ったほうで本実装する。

### ゲート（本実装の前に）

> GreBerta が gold を distractor から区別できるか。dev 200 トークンで gold の順位が乱択（候補集合内一様）より有意に良いこと。
> **信号が皆無ならここで止める**（本実装に進まない）。

### 判定規則（測定前に固定）

> **基準線**: R0 dev recall@5 **75.3%**
> **採択**: dev recall@5 **≥81.3%**（+6.0pt、H2 と同一閾値）かつ対比較ブートストラップ 95% 区間がゼロを除外
> **棄却**: 下回れば**文脈信号を完全に閉じる**
> **test は採択時に一度だけ。**

**多重性**: 採点設計2案 × 重みグリッドを一つの基準線に対して比べる。報告する見出しはセル横断の最大点推定であり、選択で上方バイアスがかかる。+6.0pt という閾値を既知の +4.1pt より上に置いたのはこのバイアスを吸収するためである。α補正は行わず、最大セル以外に主張を持たせない。全セルを結果 JSON に書き出して選択過程を検証可能にする。

**棄却された場合の含意**：「カウントベースも文脈化モデルも上限を示した」となり、打ち止めの主張が桁違いに強くなる。これは空振りではなく、**同等に有用な結論**である。

`rlb_bert.py` にゲートを実装済み（(A)(B) 両採点器、平均正規化順位で乱択 0.5 と比較）。**正式実行の手順は `--n 200` を明示して実行することだが、この手順は未実施である。**2026-08-13 の実行実績は、既定値 `--n 100` のまま走らせた100トークンである。**環境構築が回線速度で律速されている。**

| transformers (PyPI) | 小 | — | 取得中 |

### 重みが無くても決着した3点（tokenizer と vocab のみで解析、2026-08-13）

`vocab.json` / `merges.txt` / `tokenizer.json` は取得済みなので、**モデル重みを待たずに**事前登録した落とし穴の2つと採点設計の選択が確定した。

**① NFC/NFD（落とし穴2）— 解決。** GreBerta の語彙 52,000 のうちギリシャ語に復号されるのは 48,432 個で、そのうち結合文字を含むのは**わずか5個**。つまり語彙は実質 **NFC**。さらに `tokenizer.json` の `normalizer` は **`null`**——**トークナイザは正規化を一切行わない**ので、入力を NFC に正規化する責任は完全に呼び出し側にある。第2次 §3.2 の GLAUx NFD 事故と同じ構造の罠が、ここでも待っていた。

**② 採点設計 (A) vs (B) — (B) は構造的に使えない。**

design (B) は単一マスク位置の softmax を読むので、**語彙に単独トークンとして存在する語しか採点できない**。dev で実測：

| | 単独トークン率 |
|---|---:|
| gold レンマ（(A) の対象） | 39.6% |
| reg 表層形（(B) の理想的対象） | 46.6% |
| **候補レンマ @20（(B) が実際に採点すべき対象）** | **18.7%** |

**(B) は候補の 81.3% を原理的に採点できない。**設計時に「閉じた語彙なので OOV の床の利点が部分的に失われる」と書いたが、実測すると「部分的」どころではなかった。**したがって (A)（候補を差し込んで subword ごとの PLL）が唯一の実行可能な設計であり、ゲートでの比較は不要になった。**皮肉なことに、これは機構論（OOV の床が無いことが利点）が支持する設計と一致する。

(B) は本測定では使わない。ただし「単独トークンの候補に限れば (B) は (A) より安定か」という診断としては意味があるので、補助指標として残す。

**③ 長さ正規化（落とし穴1）— 定量化され、必須と確認。** merges.txt から BPE を再実装して subword 数を実測：

| | 平均 | 中央値 | 最大 | 1トークン率 |
|---|---:|---:|---:|---:|
| gold レンマ | 1.89 | 2 | 5 | 39.6% |
| 候補 @20 | 2.21 | 2 | 8 | 18.7% |

**同一候補リスト内の subword 数のばらつきは平均 2.24、最大 7。**対数尤度の素の**合計**を使えば、短い候補が系統的に有利になる（8 subword の候補は 1 subword の候補より必ず低いスコアになる）。**subword 数での平均化は装飾ではなく律速的な設計判断である。**`rlb_bert.py` の `pll()` は既に平均で実装済み。

**④ 残る未解決は効果量のみ。**機構・設計・前処理は確定し、あとは GreBerta の重み（504MB）が届けば `rlb_bert.py` のゲートと本測定がそのまま走る。

## H8 — 表層形採点 (C) は、レンマ採点 (A) の分布不一致を解消するか

**登録**: H8 の測定前（2026-08-13）に、H6 の診断を受けて追加。ただし上流の正式200トークンゲートが未完了なので、H8 を含むこの分岐全体は探索的に扱う。

### 仮説

H6 の失敗は、モデルの能力ではなく**採点対象の選び方**に起因する（gold reg 表層形は gold レンマより平均 1.685 nats [1.108, 2.261] 高く採点される）。候補レンマそのものではなく、**その候補が取りうる屈折形のうちクエリ綴りに最も近いもの**を採点すれば、分布不一致は消え、かつ (A) の「OOV の床が無い」性質は保たれる。

### 屈折形の選択規則（測定前に固定）

候補 `(lemma, cost, ff, lf, src_key)` に対し：

1. `forms = [f for f, _ in lex.forms_for_key(src_key) if lemma in lex.lemmas(f)]`
2. `b1_key(f)` と **`b1_key(クエリ綴り)`** の Levenshtein 距離を最小化
3. 同点なら**結合文字（アクセント）が多いほう**を採る——実際のギリシャ語テキストはアクセント付きであり、学習分布に近い（`rlb_ladder._accents` と同じ規則）
4. さらに同点なら辞書順
5. `forms` が空なら (A) と同じくレンマ自体を採点する（フォールバック、件数を記録）

### リーク防止（重要）

選択に使ってよいのは**クエリ綴り（パピルスに書かれた形）だけ**である。これは推論時に利用可能な唯一の情報だからである。**`reg` や `gold` を使って形を選ぶことは禁止**——それは答えを見て選ぶことになる。実装では `row["form"]` のみを参照し、`row["reg"]` / `row["gold"]` は参照しない。コードレビューでこれを確認する。

### 判定規則（H2・H6 と同一閾値）

> **基準線**: R0 dev recall@5 **75.3%**
> **採択**: dev recall@5 **≥81.3%**（+6.0pt）かつ対比較ブートストラップ 95% 区間がゼロを除外
> **棄却**: 下回れば**文脈化モデル経路を閉じる**。(A) レンマ採点・(C) 表層形採点の両方が失敗したことになり、「文脈信号は打ち止め」が (C) の留保なしに言える。
> **test は採択時に一度だけ。**

### 補助診断（判定には使わない）

- 選択された形が `reg` と一致する率——選択規則の質の上限を示す
- `forms` が空でフォールバックした率
- gold 候補について、選択形の PLL とレンマの PLL の差（H6 の診断の再現）

### 補助診断の結果（測定と並行、dev、gold が上位20位以内の 561 トークン）

### 機構 — 私の H6 での解釈は誤っていた

原因を切り分けるため、レンマ→屈折形の切り替えが gold と distractor のどちらをより持ち上げるかを測った（dev 120トークン）：

探索的測定から最も整合的な機構はこうである：

> **R0 の順位付けが既に強く、PLL はそれに比べて遥かに雑音が多い。**ゲートで測ったとおり、PLL 単独の gold 平均正規化順位は **0.368**、R0 は **0.072** である。平均的には情報を持つ（差分 +1.5 nats）が、分散が大きく（gold の区間 [+0.8, +2.7]、distractor [−0.5, +0.9] は重なる）、個別のトークンでは distractor が勝つことが頻繁にある。**強いベースラインに、平均的にしか正しくない雑音の多い信号を混ぜれば、期待値として悪化する。**
