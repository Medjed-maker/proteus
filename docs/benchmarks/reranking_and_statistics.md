## 1. 統計：文書クラスタブートストラップ

test は 1,488トークンだが独立単位は **222文書**である。同一パピルスのトークンは
書記者の癖を共有するため、dev/test を文書単位で切った論理は区間にも同じ要求をする。

- **文書単位ブートストラップ 1,000回**（`rlb_stats.py`）。対比較は同一リサンプル内で
  差を取るペアード方式。これが主指標。
- **McNemar 完全二項検定**を副次で併記。検出力は高いがトークン独立を仮定するので楽観的。
  両者が食い違う場合はクラスタ区間を採る。
- 健全性確認：同一系同士の差の区間が [+0.0%, +0.0%] に退化することを確認済み。

第1次の結果ファイルには文書IDが無かったため、データセット順の位置結合で復元し、
**全2,160行で `form` / `gold` / `split` の一致を検証**した（1件でも不一致なら中止する実装）。

### 1.1 すべての効果は k に依存して符号が反転する

recall@k の差（%ポイント）、95%区間、`*` は区間がゼロを含まない。

| 比較 | @1 | @5 | @20 |
|---|---|---|---|
| B3ur vs B2u（15交替 vs 素の距離） | **+3.2 [+0.5, +5.9]\*** | +2.8 [−0.1, +5.5] | **−2.4 [−4.3, −0.7]\*** |
| B3u vs B3（union vs カスケード） | **+0.7 [+0.1, +1.4]\*** | **+12.6 [+10.6, +14.7]\*** | **+20.8 [+18.3, +23.2]\*** |
| R5r vs R0（実POSタガー） | **−3.4 [−5.9, −1.1]\*** | +0.9 [−0.8, +2.7] | **+1.9 [+0.3, +3.6]\*** |
| R5 vs R0（gold POS・上限） | **+5.8 [+3.3, +8.3]\*** | **+9.5 [+7.6, +11.4]\*** | **+5.6 [+3.9, +7.5]\*** |
| R1 vs R0（加法スコア化） | **−4.5 [−7.1, −1.9]\*** | −0.9 [−2.9, +0.9] | **+2.0 [+0.4, +3.7]\*** |

**符号が k によらず一定なのは、カスケードの害（B3u vs B3）と gold POS の2つだけである。**
他はすべて「頭を取るか裾を取るか」のトレードオフであり、
単一の k で「効く／効かない」と述べるのは誤りだった。

### 1.2 事前分布の固有寄与はゼロ（第1次の訂正）

R2〜R6 はいずれも R1（加法スコア）に事前分布を足したものである。
第1次はこれらを R0（辞書式）と比較したため、**事前分布の効果と
スコア形式の変更が交絡していた**。R1 を基準に取り直すと分離できる。

| 比較 | @1 | @5 | @20 |
|---|---|---|---|
| R2 vs R1（時代のみ） | +0.3 [−0.3, +0.9] | −0.1 [−0.4, +0.2] | +0.0 [+0.0, +0.0] |
| R3 vs R1（方言のみ） | −0.2 [−0.9, +0.6] | −0.3 [−0.9, +0.4] | +0.1 [−0.3, +0.6] |
| R4 vs R1（ジャンルのみ） | +0.2 [−0.5, +0.9] | −0.5 [−1.2, +0.1] | +0.3 [−0.1, +0.7] |
| R6 vs R1（すべて） | −0.3 [−1.0, +0.4] | +0.1 [−0.6, +0.8] | +0.1 [−0.1, +0.3] |

**すべて |差| ≤ 0.5pt、すべての区間がゼロを含む。**
時代・方言・ジャンルの事前分布は、順位付けを改善も悪化もさせない。**何もしない。**

第1次で観測された「約1ポイントの悪化」は、事前分布ではなく
**辞書式順序を加法スコアに置き換えたこと**に帰属する（R1 vs R0 が @1 で −4.5pt）。
結論（B5「方言・時代制約」の優先度低下）は変わらないが、**理由が違う**。
「有害だから使わない」ではなく「無効だから使わない」が正確である。

## 2. ③交替確率タイブレーカ — 棄却

### 2.1 事前登録した判定基準と結果

> test の recall@5 改善が +3.0pt 未満、または区間がゼロを含むなら③を棄却する。

P(交替) は **test に含まれない173文書**（dev 88 ＋ 評価トークンを持たない85）から推定した。
714組の綴りペア、814の交替サイト、82種。ダウンロード不要、リークは構成上ゼロ。

| 変種 | dev recall@5 | test recall@5 | test 対R0 |
|---|---|---|---|
| R0（基準） | 74.6% | 72.8% | — |
| A1 頻度より前でタイブレーク | 67.7% | 64.9% | −8.0 [−10.4, −5.7] |
| A2 整数コストを置換 | 43.9% | 42.7% | −30.1 [−33.5, −26.2] |
| A4 頻度の後でタイブレーク | 74.6% | 72.7% | −0.1 [−0.3, +0.0] |
| A5 加法の微調整（w=0.2、dev選定） | 74.9% | 72.6% | **−0.3 [−0.7, +0.1]** |

**③は棄却。**経験的行列は「ランキング部品」ではなく科学的成果物としてのみ維持する。

### 2.2 なぜ効かないのか（機構の特定）

仮説の前提「候補が同コスト帯で団子になっている」は**正しい**。
上位60候補内で同一コスト帯にまとまる最大群の中央値は36件、
頻度を入れても10件で、95.4%のトークンに2件以上の団子が残る。
5位圏外に沈んだ gold の 99/122 件は、実際にその団子の中にいる。

にもかかわらず効かない理由は、団子の**中身**にある。

- 5位圏外の gold を含む同値グループのうち、**76.8% は交替コストのばらつきが 0**。
  つまり群のメンバー全員が**同じ交替**でクエリに到達している。
- 残り23.2%でも、gold は群内で交替コスト順に見て既に最良（中央値 0.00、平均 0.09）。

**団子は「同じ交替を共有しているからこそ団子になっている」。**
その共有物を並べ替えの鍵にすることはできない。
③が測っていなかったのは事実だが、測れば構造的に効かないことが分かる種類の仮説だった。

## 3. 文脈 n-gram — 採択（本再測定の主成果）

### 3.1 リーク照合の結果（前提の訂正）

計画時に「GLAUx は PapyGreek を取り込んでいる」と述べたが、**これは誤りだった。**
公開されている GLAUx コーパスの `metadata.txt`（1,421テキスト・19.5Mトークン）を
実際に照合した結果：

- パピルス・文書系のジャンルは **0件**。生テキストの出所は Perseus / First1KGreek / Wikisource、
  注釈層は AGDT / PROIEL / Pedalion / Gorman / Harrington / Aphthonius で、PapyGreek は含まれない。
- TM id の一致は37件あるが**すべて名前空間の衝突**である。Trismegistos は文学作品と
  文書テキストを別体系で採番しており、TM 705 は GLAUx ではデモステネス『冠について』、
  PapyGreek ではゼノン文書アーカイブのパピルスを指す。

**したがってリークは無い。同時に、in-domain データも無い。**
リスクは汚染ではなく**ドメインのずれ**だった。

### 3.2 構成

- **レンマ三つ組・stupid backoff**（α=0.4）を自作した。候補集合がレンマなので、
  表層形のLMを使うと写像がもう一段挟まり誤りが乗る。
  Dilemma 同梱の `train_lm.py` は iOS 向けバイナリを吐き、pip パッケージに読み手が無く
  語彙も切り詰められているため、数える方が安い。
- **コーパス**: GLAUx の XML を `raw.githubusercontent` からストリームし、レンマ列だけを残した。
  アーカイブ一括取得はこの環境で完走しなかったため、パピルスの年代域（BCE300–CE700）と
  重なる919テキストから**大きい順に30本**を取り、各本を時間上限付きで先頭から取得した。
  結果 **44,094文・1,036,543レンマ**（全体の約7%）。
- **文脈**: 同一 doc/sent の直前2語。上限値として gold レンマ、
  実運用値として **Dilemma で `guess=False` レンマ化した予測**の両方を測った。
- スコア: コスト帯は保持し、帯内で `log(形頻度) + w · log P_LM(候補 | 前2語)`。
  w は **dev で選定**（2.0）、test は一度だけ測定した。

**重要な落とし穴**: GLAUx は NFD、PapyGreek と Dilemma は NFC である。
正規化せずに突合すると gold レンマの被覆が **0.4%** になり、
「文脈は無力」という誤った結論に直行する。NFC 正規化後の被覆は
gold 84.5% / 文脈語 87.3% / 上位20候補 50.6%。

### 3.3 結果

| 構成 | dev recall@5 | test recall@5 | test 対R0 |
|---|---|---|---|
| R0（基準） | 74.6% | 72.8% | — |
| ＋LM文脈（gold レンマ・上限） | 77.8% | 76.9% | +4.0 [+2.8, +5.2] |
| **＋LM文脈（Dilemma 予測・実運用）** | 77.7% | **77.1%** | **+4.2 [+3.0, +5.5]** |

**実運用構成が上限とほぼ同値**である。POS では実タガーが信号を壊したが、
文脈語の約9割は `clean` 層の標準綴りで、Dilemma は `guess=False` でも
33,615語中32,230語（95.9%）を解決するため、ここでは劣化がほとんど起きない。

読み手のコストで見るとさらに明瞭である。

| 指標 | R0 | ＋LM文脈 |
|---|---|---|
| gold 順位の中央値 | 1 | 1 |
| gold 順位の p90 | 24 | **12** |
| recall@1 | 52.8% | 52.2% |
| recall@5 | 72.8% | **77.1%** |
| recall@20 | 82.7% | **86.0%** |
| 全変異語を5位以内で解決できた文書の割合 | 31.5% | **39.2%** |

**頭を犠牲にせず裾を半分に畳んでいる。**

### 3.4 コーパス量の寄与は小さい（dev のみで測定）

主測定の後、中断していたアーカイブ取得が切断点まで書き込みを終えていたため、
1,027ファイル（GLAUx の約72%）がローカルに復元できた。
これで**現行の10倍以上**のコーパスが使える。

test の測定は既に一度使い切っているので、**dev のみで測った**。

| 学習コーパス | レンマ数 | 語彙 | gold被覆 | 候補被覆 | dev 対R0（最良 w） |
|---|---|---|---|---|---|
| 30本（ストリーム取得） | 1,035,543 | 29,008 | 84.5% | 50.6% | +3.1 (w=2.0) |
| 全量・年代域内632本 | 10,274,310 | 94,817 | 89.4% | 69.8% | **+3.6 (w=1.0)** |
| 全量1,027本（年代フィルタなし） | 14,393,438 | 108,624 | 89.7% | 72.9% | **+3.6 (w=1.0)** |

**10倍のデータで +0.5ポイント。**収穫逓減が著しい。

読み取りは2つある。

1. **被覆は律速要因ではなかった。**gold レンマの被覆は 84.5% → 89.7% と改善するが、
   同時に**候補側の被覆も 50.6% → 72.9% に上がる**。語彙が増えると正解だけでなく
   競合もスコアされるようになるため、差し引きの利得は小さい。
   LM が寄与しているのは、100万語でも既に捉えられる**強い高頻度の連鎖**である。
2. **年代フィルタは無意味だった。**年代域内10.3Mと全量14.4Mが同値（+3.6）。
   どちらも文学ギリシャ語である以上、パピルスとの距離は年代では縮まらない。
   §3.2 で年代で絞ったのは、結果的に不要な手間だった。

**したがって test の測り直しは見送る。**dev で +0.5pt の差なら、
test の +4.2pt が +4.7pt 程度になるだけで結論は動かず、
test セットへの2回目の参照に見合わない。
報告値は 100万レンマ構成の **+4.2pt [+3.0, +5.5]** を据え置き、
これは**下限**として読むべき値である。

### 3.5 なぜ POS より効いたのか

POS は文脈から**品詞という中間表現**を経由し、その誤りがそのまま乗る
（Dilemma の POS ヘッドは原綴りで正解率 56.9%、冠詞 0.0%）。
n-gram は候補レンマを**直接**スコアするので中間表現が無い。
第1次で「律速はタガーの精度」と結論したが、より正確には
**律速は中間表現を経由すること自体**だった。

なお伸びしろについては §3.4 を参照。10倍のデータでも dev で +0.5pt にとどまる。

## 4. 指標の変更：precision@5 を撤回する

第1次の §7-2 で「受入基準を recall@5 から precision@5 / MRR へ移すべき」と書いたが、
**precision@5 は撤回する。**

precision@5 は余分な候補を返すことを罰する。これは
`8.2 学術上の制約`「候補は確定判断ではなく根拠付き仮説として提示する」と真っ向から衝突する。
研究インフラで致命的なのは**偽陰性**（正解が候補にない）であって偽陽性ではない。

代わりに以下を主指標とする。

- **recall@N を維持**（N=5, 20, 50 を併記し、裾を可視化する）
- **gold の順位の中央値／p90** — 研究者が正解に到達するまでに何件読むか
- **coverage@k** — 変異語をすべて k 位以内で解決できた**文書**の割合。
  1語でも未解決なら、その文書はパピルス学者にとって未解決である

3つ目は「何件返したか」ではなく「**何件読ませたか**」を測る。
第1次で指摘された「|C| 中央値179は読めない」という問題は、この指標で直接可視化される
（R0 の coverage@5 は 31.5% にすぎない）。

「B4は不要」の判定には性質の異なる3用途が混在していた。再測定で全て決着した。

| 用途 | 判定 | 根拠 |
|---|---|---|
| ① **生成器**としての素性空間距離 | **死んだ** | 未生成バケツは4.3%、内訳は重度の破損・断片で連続距離の対象外 |

ただし §2 の科学的成果物としての価値は残る（時代・出土地で条件付けた推定値は
それ自体が論文の中身になる）。

## 6. 製品形態への含意：ファセット絞り込み

自動順位付けの現状は次のとおりである。

| | recall@5 |
|---|---|
| oracle（完全な順序付け） | 92.3% |
| R0 | 72.8% |
| ＋文脈n-gram（実運用） | **77.1%** |
| ＋gold POS（到達不能な上限） | 82.3% |

**文脈n-gramで 19.5pt の隙間のうち 4.2pt が埋まった。残りは 15.2pt である。**
第1次測定の時点では「機械が自動で並べ替える道はほぼ閉じている」と読めたが、
それは言い過ぎだった。道は開いており、ただし狭い。

その上で、**gold POS なら +9.5pt** という事実は依然として重要な含意を持つ。
その情報を**持っている主体が存在する**ということである。パピルス学者は文脈を読んでいるので、
「これは動詞」「これは人名」「与格が来るはず」を即座に言える。
タガーには出せない情報が、ユーザーの頭の中にある。

したがって UI は「検索窓 → ランク付きリスト」ではなく、
**候補空間のファセット絞り込み**であるべきだと考えられる。

```text
入力: κοίριος
→ 候補 179件（recall@∞ 92.3%）
→ [品詞] [方言] [時代] [適用交替] [語頭文字] でファセット
→ 研究者が「名詞」を指定 → 12件
→ 各候補に適用ルール・出典・類例
```

この設計には3つの利点がある。

1. **弱いタガー問題が消える。**機械が推測する必要がなくなる。
2. **時代・方言が復活する。**§1.2 のとおりランキング信号としては無効だが、
   それは分布が正解と競合を区別しないからである。
   研究者が「これはプトレマイオス朝だ」と*指定*すれば絞り込みは効く。
   **「説明／ランキング」の二分に、第三の用途＝フィルタを加えるべきである。**
3. **`8.2` の位置づけと整合する。**機械が確定せず、研究者が判断する。

この設計では主評価が変わる。自動精度ではなく、
`deep-research-report.md` の `expert alone / expert + Dilemma / expert + HPSI` の
三条件比較による **to-resolution 時間**が主指標になる。

**ただしこれは仮説であって、測定ではない。**本測定はファセットUIを検証していない。
検証には実際のパピルス学者による比較評価が要る。

## 7. 残る課題

0. **ファセットUIの検証**（§6）。人間が必要で、本測定の射程外。
1. ~~文脈LMの全量学習~~ — §3.4 で決着。10倍のデータで dev +0.5pt にとどまる。
   伸ばすなら量ではなく**ドメイン**（文書パピルスの走行テキスト）が要る。
2. **LM と POS の併用は未測定**。両者は異なる誤りを直す可能性がある。
3. **文脈語のレンマ化は Dilemma に依存**している。自前で閉じるなら Layer 1 の再帰適用が要る。
4. 第1次測定の限界（`KEY_CAP=300` の打ち切り、分割実行段の strict 欠測、
   単一コーパス）はすべて継承される。
