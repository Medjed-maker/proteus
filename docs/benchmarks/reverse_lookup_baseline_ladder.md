## 1. 結論

| 主張 | 実測 |
|---|---|
| 事前予測「B3 だけで recall@5 は 55〜70%」 | **的中**。60.3%（カスケード）/ **72.8%**（union） |
| 音韻距離行列への投資は正当化されるか | **されない**。残存失敗の **81.6% は生成でなくランキングの失敗** |
| 手書き15交替は素の編集距離を上回るか | **上回るが差は小さい**。recall@5 で +2.8pt、recall@1 で +3.2pt |
| 15交替の価値はどこにあるか | 再現率ではなく **精度と速度**。実行時間 1/3、候補集合 |C| p90 が 14 対 203 |
| (a) 19.1% はいくら回収できるか | **文脈n-gramで +4.2pt**（72.8%→77.1%）。POS は信号としては +9.5pt あるが実タガーでは取れない |
| 方言・時代制約は再ランキングに効くか | **効かない**。※訂正: 「悪化する」ではなく**何もしない**（固有寄与 ≤0.5pt、区間はゼロを含む）。[続編 §1.2](reranking_and_statistics.md) |

**最重要**: 事前登録したタイブレーク基準
「(a) 候補内にあるが5位圏外 / (b) そもそも候補に入らない」の比は **81.6% 対 18.4%**。
(a) が支配的である以上、問題は距離モデルの表現力ではなく候補の並べ方であり、
音韻距離行列はこれを解かない。B4 は着手すべきでない。

## 2. 設計 — 同一辞書・異なる探索戦略

Dilemma とまったく同じ辞書を索引に使い、探索戦略だけを差し替える。
これで「向こうはデータが多いから」という交絡が消える。

| 資源 | 規模 | 用途 |
|---|---|---|
| `lookup.db` `lookup` 表 | 9,726,344 form→lemma | 表層形からレンマへ |
| `spell_index.db` `spell` 表 | 6,110,716 stripped→forms | アクセント除去キー。うち古典ギリシャ語 4,804,367 |
| `corpus_freq.json` | 1,126,568 form / 67.8M トークン | ランキング（形頻度） |
| `lemma_attestation.json` | 763,487 lemma | ランキング（レンマ頻度） |

頻度表は GLAUx / Diorisis / PatristicTextArchive 由来で PapyGreek を含まない。
**ランキングに評価データの漏洩はない。**

Dilemma 自身の使い方との意図的な相違は2点。

1. Dilemma の `LookupDB.get()` は `LIMIT 1` で単一レンマを返す。ここでは形に紐づく
   レンマ集合を全部返す。**候補集合を返せること自体が評価対象**だから。
2. あいまい検索の対象は `src='grc'` の項目のみ。パピルスの綴りを現代ギリシャ語の
   正書法に照合するのは言語学的に意味がなく、かつ真部分集合なので保守側に振れる。

### dev/test 分割

`variant_ortho` を**文書単位で** dev 30% / test 70% に分割し `splits.json` に固定
（88/310文書、dev 672 / test 1,488トークン）。文書単位にしたのは、綴りが書記者ごとに
相関し、同一パピルスの2トークンは独立した証拠ではないため。

15交替リストは**測定前に凍結**した（`rlb_keys.py` の `ALTERNATIONS`）。
以下に示すとおり dev と test の差は最大 1.8ポイントで、過適合は起きていない。

| (2) 正解レンマ `lemma_gold` が辞書に存在 | 2,059 | **95.3%** |

先行する lenient 一致で strict 候補の探索を打ち切っていた集計不具合を修正して再測定した値である。

### 4.1 カスケードは誤りだった

当初 B2/B3 は「安い手法が当たったらそこで止める」カスケードで実装した。
これは中立な設計判断ではない。**書記者の誤綴りはしばしば別の実在語**である
（`πεδίων` は `παιδίων` の誤綴りであると同時に `πεδίον`「平野」の正規形）。
そのため完全一致が成功して誤ったレンマを返し、交替ルールが一度も走らない。

この早期打ち切りだけで B3 の recall@∞ は 62.2% に抑え込まれていた。
生成器を競合させる union にすると **92.3%** になる。差は 30ポイントである。
実測前に (b) と分類された失敗 304件のうち **176件は、等価類キーが一致していたのに
呼ばれなかっただけ**だった。

これは Proteus の実装に直接効く知見である。**逆引きでは「入力がそのまま辞書に載っている」
ことを打ち切り条件にしてはならない。**

#### 4.1.1 これは古代ギリシャ語固有の話ではない

打ち切り条件になっているのは「語彙目録に載っていること」であり、
**歴史的表記正規化の既存パイプラインはほぼ例外なくこれを正常判定に使っている**
（VARD、Norma、CAB、そして Dilemma 自身）。
`πεδίων` のような **real-word error**（誤綴りが別の実在語と一致する事例）は、
その設計では原理的に検出できない。

本測定はその損失を初めて定量化した：**recall@∞ で30ポイント**。
古代ギリシャ語のパピルスで測ったが、機構は言語に依存しない。
高度に屈折する言語ほど、また正書法が未固定な資料ほど、
誤綴りが別の実在語に着地する確率は上がる。

したがって本測定の貢献は「ギリシャ語の新ツール」ではなく、
**歴史的表記正規化の設計原理に対する反証**として位置づけるのが正確である。

### 4.2 15交替の実効値

union 同士で比較すると、交替リストの寄与が分離できる。

| | recall@1 | recall@5 | 時間 | \|C\| p90 |
|---|---|---|---|---|
| B2u（言語知識ゼロ） | 48.3% | 68.1% | 1,188s | 593 |
| B3ur（15交替のみ） | 51.5% | **70.9%** | **401s** | 618 |
| B3u（両方） | 52.8% | 72.8% | 1,577s | 1,015 |

15交替は素の編集距離を **recall@5 で +2.8pt、recall@1 で +3.2pt** 上回り、
かつ **実行時間が1/3**。素の距離を足しても +1.9pt しか増えない。

カスケード同士（B3b 対 B2）ではさらに明瞭で、recall@5 はほぼ同値（59.7 対 59.2）ながら
**候補集合が p90 で 14 対 203、実行時間が 125s 対 723s**。
**交替リストが買っているのは再現率ではなく、精度と速度である。**

## 5. 判定 — (a)/(b) 分解

事前登録したタイブレーク基準。B3u（最良段）、test 分割。

| 区分 | 件数 | 率 |
|---|---:|---:|
| recall@5 命中 | 1,084 | 72.8% |
| (c) 到達不能（正解レンマが辞書に無い） | 56 | 3.8% |
| **(a) 候補集合には在るが5位圏外 → Layer 2 の課題** | **284** | **19.1%** |
| **(b) そもそも生成されない → Layer 1 の課題** | **64** | **4.3%** |

到達可能な 1,432件に限れば recall@5 は 75.7%、失敗の内訳は
**(a) ランキング 81.6% 対 (b) 生成 18.4%**。

残る (b) 64件の内訳は「その他の置換」8、「複数交替の重畳」7、「長い削除」5+4、
以下すべて一桁で、**体系的な音韻交替ではなく重度の破損・断片**である。
音韻素性空間の連続距離が拾える対象ではない。

### 5.1 (a) 19.1% はいくら回収できるか — 再ランキングの実測

(a) が支配的だと分かった以上、次の問いは「その 19.1% は実際いくらの価値があるか」である。
**生成器を B3u に固定し、順序付けだけを差し替えて**測った。
候補集合を素性つきで一度ダンプし（`dump_b3u.jsonl`、2,160トークン）、
各案はその再スコアリングとして実行しているので、探索は一度きりである。

使える信号はすべて Dilemma 同梱の表から取り、PapyGreek 由来のものは無い。

| 信号 | 出所 |
|---|---|
| 形頻度 / レンマ頻度 | `corpus_freq.json` / `lemma_attestation.json` |
| **時代** `by_century` | `lemma_attestation.json` × パピルスの年代（`date_not_before/after`） |
| **方言** `by_dialect` | 同上。文書パピルスは Koine |
| **ジャンル** `by_genre` | 同上。`epistles` が最も近い |
| **POS** `dominant_pos` | 同上 × PapyGreek の gold POS |

| R1 加法スコアへ変更 | 48.3% | 65.3% | 71.9% | 79.6% | −0.9 |
| R2 ＋時代事前分布 | 48.5% | 66.0% | 71.8% | 79.5% | −1.0 |
| R3 ＋方言事前分布 | 48.1% | 65.7% | 71.6% | 80.5% | −1.2 |
| R4 ＋ジャンル事前分布 | 48.5% | 66.0% | 71.4% | 79.9% | −1.5 |
| R6 事前分布すべて（POS 無し） | 47.9% | 65.9% | 72.0% | 80.3% | −0.9 |
| **R5r ＋POS（Dilemma 実タガー・原綴り）** | 49.3% | 66.0% | **73.8%** | 79.5% | **+0.9** |

#### 読み取り

**1. 時代・方言・ジャンルの事前分布は効かない。**
> **訂正（第2次測定）**: 以下の「1ポイント程度悪化する」は誤りである。
> R2〜R6 は R1（加法スコア）に事前分布を足したものなので、R0 との比較は
> 事前分布の効果とスコア形式の変更を交絡させていた。R1 を基準に取り直すと
> 事前分布の固有寄与は **|差| ≤ 0.5pt、区間はゼロを含む**。
> 悪化していたのは事前分布ではなく加法スコア化そのものである。
> 結論（B5 の優先度低下）は変わらないが、理由は「有害」ではなく**「無効」**。
> 詳細は [reranking_and_statistics.md §1.2](reranking_and_statistics.md)。

第1次測定の記述: それどころか一貫して 1ポイント程度悪化する。
重みを 0〜8 で掃引しても改善は最大 +0.3ポイント（dev、誤差の範囲）、
時代を**ハード制約**（該当世紀に用例のないレンマを除外）にすると 73.5% → 71.4% とさらに悪化した。

理由は明快である。これらの事前分布は**正解候補と競合候補をほとんど区別しない**。
どちらも同じ時代・同じ方言・同じジャンルの語彙だからである。
分布が効くのは候補が時代的に散らばっている場合だが、逆引きの候補集合は
綴りが似た語の集合であって、時代で散らばってはいない。

**これは B5「方言・時代制約」に対する直接の反証である。**
少なくとも文書パピルスの逆引きにおいては、時代・方言制約は再ランキング信号として機能しない。

**2. POS は信号としては大きいが、実タガーではほぼ取れない。**
> **補足（第2次測定）**: この「+0.9ポイント」は k に依存する。
> recall@1 では **−3.4pt（有意に悪化）**、@5 では有意差なし、@20 では **+1.9pt（有意に改善）**。
> 実タガーは頭を犠牲にして裾を縮める。単一の k で「効かない」と述べるのは不正確だった。

gold POS なら +9.5ポイント。しかし **Dilemma 自身の POS ヘッドを実際に通すと +0.9ポイント**
にとどまり、しかも recall@1 は 52.8% → 49.3% と **3.5ポイント悪化**する。

差の全量はタガー精度である。Dilemma の POS ヘッドの本データでの正解率は

| 入力 | 全体 | ヘッドが出力しうる品詞に限定 |
|---|---|---|
| 原綴り（実運用の条件） | **56.9%** | 59.7% |
| 校訂綴り（同タガーの上限） | 65.9% | 69.1% |

品詞別に見ると崩壊は明白である。動詞 80.7%、名詞 67.9% はまだしも、
**冠詞 0.0%、副詞 1.0%、数詞 3.6%、代名詞 19.2%**。
そもそもこのヘッドは `particle` / `conjunction` / `interjection` を**出力できない**
（本データの 100件の接続詞は全滅する）。予測分布も 2,160件中 1,014件が `verb` で、
動詞へ強く偏っている。

原綴りと校訂綴りの差（56.9% 対 65.9%）は9ポイントあるが、
**再ランキングへの影響は +0.9 対 +1.1 とほとんど無い**。
つまり律速は「誤綴りがタガーを壊すこと」ではなく、**タガーがこの領域でそもそも弱いこと**である。

感度曲線（dev, recall@5）: 誤り 0% → 82.6%、5% → 82.1%、10% → 81.5%、20% → 78.1%、
**実測 43% → 75.6%**。前節で +7.6ポイントと見積もったのは誤り率10%を仮定したためで、
**実測値はその 1/8 である。**

**3. (a) バケツの回収も 32% にとどまる。** R0 で「生成されたが5位圏外」だった
到達可能な 283件のうち、実タガーによる再ランキングが5位以内へ引き上げたのは
**91件（32.2%）**。一方で 77件を5位圏外へ押し出しており、差し引き +14件しかない。
（誤り率10%の仮定では 164件・58.0% を救出し、脱落は 51件だった。）

| 遷移 | 実タガー R5r | 誤り率10%の仮定 R5n |
|---|---:|---:|
| 5位以内を維持 | 1,007 (67.7%) | 1,033 (69.4%) |
| **5位以内へ救出** | **91 (6.1%)** | **164 (11.0%)** |
| 5位以内から脱落 | 77 (5.2%) | 51 (3.4%) |
| 依然不足 | 313 (21.0%) | 240 (16.1%) |

**4. 現状の辞書式順序付けは意外に強い。** R1（加法スコアへの変更）は単独では悪化する。
コストを絶対優先する現在の並べ方は、少なくとも POS を入れるまでは適切だった。

**5. 行動可能な結論**
> **訂正（第2次測定）**: 以下の「使える POS タガーを得る」より優先すべき手が見つかった。
> **文脈 n-gram** が test で **+4.2pt [+3.0, +5.5]**（recall@5 72.8% → 77.1%）を出し、
> しかも gold 文脈を使わない実運用構成で達成している。
> POS が伸びなかった理由は「タガーが弱い」ことよりも
> 「品詞という中間表現を経由すること」自体にある。
> n-gram は候補を直接スコアするので中間表現が無い。
> 詳細は [reranking_and_statistics.md §3](reranking_and_statistics.md)。

第1次測定の記述: 行動可能な結論は「POS 再ランキングを入れる」ではなく「使える POS タガーを得る」である。
信号には +9.5ポイントの価値が実在し、oracle との差はさらに +19.5ポイントある。
しかし現在入手できるタガーはその 1/10 しか引き出せない。

Dilemma の POS ヘッドは**単語単独・文脈なし**で動く（`predict_pos_batch` は語の配列を取り、
文を取らない）。これが弱さの最有力の説明である。PapyGreek は文単位の係り受け注釈を持つので、
**文脈つきタガーの学習データはすでに手元にある**。次に測るべきはここである。

### 事前登録した判定基準への当てはめ

> **≥ 55%** → 予測的中。Layer 1 は差別化要因ではない。事業計画書 4.1 を書き換え、
> 投資を Layer 2 へ全振り。B4/B5 は中止。

B3 = 60.3%（カスケード、事前登録どおりの定義）、B3u = 72.8%（最良）。
いずれも 55% を超える。加えてタイブレーク基準の (a)/(b) 比も同じ方向を指す。

**判定: 音韻距離行列（B4）に着手しない。**

## 6. clean 層への回帰確認

緩和探索が標準綴りを壊していないか。`clean` 層の先頭 4,000（B3ur は 1,500）トークン。

| 段 | @1 | @5 | @∞ | 無候補 |
|---|---|---|---|---|
| B1 | 66.6% | 77.8% | 78.0% | 7.4% |
| B3a | 68.8% | 80.2% | 80.5% | 3.9% |
| B3ur | 70.7% | 84.3% | 95.6% | 0.2% |

**回帰なし。** 等価類の畳み込みは標準綴りでも一貫して改善する。

ただし top-1 では Dilemma が明確に上である（clean 層で lenient 90.4% 対 70.7%）。
本梯子のランキングは頻度のみで、形態論解析も文脈も使っていないため当然の結果であり、
**Dilemma を置き換えるものではない**ことを確認しておく。
`dilemma_papygreek_baseline.md` §8-5 の補完構成（Dilemma を `guess=False` で棄権させ、
棄権分を逆引きに回す）が引き続き妥当である。

## 7. Proteus への含意

1. **事業計画書 4.1 の「技術的核心は言語非依存の音韻置換フレームワーク」は書き換えを要する。**
   等価類ハッシュ＋既製辞書という1日分の実装が Dilemma の天井 34.1% を 38ポイント超えた。
   ここは差別化の源泉ではない。

2. **投資先は Layer 2 の再ランキング。ただし今すぐ効く部品は存在しない。**
   §5.1 の実測により、POS 信号には gold で +9.5ポイントの価値が実在する一方、
   **入手できるタガーでは +0.9ポイントしか取れない**（しかも recall@1 は 3.5ポイント悪化）。
   Proteus の受入基準は recall@5 から **precision@5 / MRR** へ移すべきである。

2''. **最も費用対効果の高い次の一手は「非標準綴りに耐える文脈つき POS タガー」である。**
   上限 +9.5ポイント、現状 +0.9ポイントで、差の 8.6ポイントがそのまま伸びしろになる。
   Dilemma の POS ヘッドは単語単独で動き、冠詞 0.0% / 副詞 1.0% / 数詞 3.6% と崩壊しており、
   `particle` / `conjunction` / `interjection` は出力すらできない。
   学習データは PapyGreek の文単位注釈がそのまま使える。
   **これは Layer 2 の中で唯一、上限が実測で確定している投資対象である。**

2'. **B5「方言・時代制約」は少なくとも文書パピルスでは機能しない。** §5.1 のとおり、
   時代・方言・ジャンルの事前分布はいずれも再ランキングを 1ポイント程度**悪化**させ、
   重み掃引でもハード制約化でも改善しなかった。逆引きの候補集合は綴りが似た語の集合で
   あり、時代や方言で散らばっていないため、これらの分布は正解と競合を区別しない。
   B5 は、別の根拠が出るまで優先度を下げるべきである。
   （方言帰属は**説明**としては依然価値があるが、**ランキング信号**としては無価値である。
   この2つを分けて扱うこと。）

3. **候補集合の大きさが次のボトルネックである。** B3u は \|C\| の中央値 179、p90 1,015。
   recall は高いがそのままでは読めない。Layer 2 の第一の仕事は候補生成ではなく
   **候補の剪定と順序付け**になる。

4. **15交替リストは維持する価値がある。** 再現率への寄与は +2.8pt と小さいが、
   実行時間 1/3・候補集合 1/14 という効果は、上記3の剪定問題に直接効く。
   ルールを「距離を縮める道具」ではなく「候補を絞り根拠を付す道具」として位置づけ直す。

5. **早期打ち切り禁止。** §4.1 のとおり、入力がそのまま辞書にある場合でも
   交替ルールを走らせること。実装上の必須要件とする。

6. **辞書規約差 (c) 3.8% は Layer 1/2 のどちらでも解けない。**
   レンマ規約のマッピング表（AGDT/Morpheus ↔ Wiktionary）が別途必要である。

## 8. 測定の限界

1. **B2/B2u/B3u の探索には `KEY_CAP = 300` の打ち切りがある。** 編集距離2で
   4.8M キーを引くと数千件が該当し、その全件を辞書引きすると実行時間が破綻する。
   距離順・頻度順で上位300キーのみをレンマに展開した。recall@∞ は
   この打ち切り分だけ過小評価されている（recall@5 への影響は無視できる）。

2. **strict 採点は分割実行した段で欠測。** 分割マージが lenient カウンタのみを
   再計算するため。非分割の段で差が約2ポイントに収まることを確認済み。

3. **`dominant_pos` はレンマごとに1品詞しか持たない。** 多品詞語では正解候補を
   不当に罰する。R5（gold POS）の +9.5ポイントは、この粗さを込みでの下限であり、
   品詞集合を正しく持てば信号の価値はさらに上がりうる。

3'. **実タガーの測定は文脈なしのヘッドに限られる。** `predict_pos_batch` は語の配列を
   取り、文を取らない。したがって R5r の +0.9ポイントは
   「POS 再ランキングの価値」ではなく「文脈なしタガーで取れる分」である。
   文脈つきタガーの数字は未測定で、これが次の測定対象になる。

4. **候補側の文脈も未使用。** 前後語・共起・形態素解析を一切使っていない。

5. `dilemma_papygreek_baseline.md` §7 の限界（正解データのノイズ、訓練データ混入、
   文脈非依存、単一コーパス）はすべて本測定にも継承される。

## 9. 再現手順

```bash
python -m venv .venv && .venv/bin/pip install numpy rapidfuzz
# Dilemma のデータ層（lookup.db / spell_index.db / *_freq.json）が
# ~/.cache/dilemma/data に展開済みであること

.venv/bin/python rlb_splits.py                 # dev/test 分割を固定
.venv/bin/python rlb_build.py                  # 4.8M キーの等価類畳み込み（再開可能）
.venv/bin/python rlb_b0.py                     # 到達可能性の上限
.venv/bin/python rlb_ladder.py --stages B1 B3a B3b B3
.venv/bin/python rlb_ladder.py --stages B3ur
.venv/bin/python rlb_ladder.py --stages B2u --offset 0 --limit 700   # 分割実行
.venv/bin/python rlb_merge.py results_b2u.json results_b2u_*.json
.venv/bin/python rlb_analyze.py --stage B3u    # (a)/(b) 分解

# 再ランキング（§5.1）。候補を素性つきでダンプしてから再スコアリングする
.venv/bin/python rlb_ladder.py --stages B3u --offset 0 --limit 550 \
  --out results_b3ud_0.json --dump dump_b3u_0.jsonl        # 分割実行
cat dump_b3u_*.jsonl > dump_b3u.jsonl
.venv/bin/python rlb_rerank.py --split dev     # 案の選定はこちらで
.venv/bin/python rlb_rerank.py --split test    # 最終測定は一度だけ
```

`variant_ortho` 全段の総計算時間は約 1.5 時間（うち B2u/B3u が約 45 分）。
